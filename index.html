Projects

Pokemon Team Analyzer

In progress May 2026 – Present

The spark

I've been a Pokemon fan for as long as I can remember, and every playthrough came down to the same puzzle: six party slots, hundreds of choices, and one bad type matchup could sink the whole team. I wanted a tool that would spot those weak points before an opponent did, so I started building one that maps out a team's type coverage and uses AI to suggest how to make it stronger.

A full-stack app that analyzes a Pokemon team's composition and type coverage.

  • React and TypeScript frontend that pulls structured data from the PokeAPI and surfaces team composition and type coverage.
  • Node and Express backend that validates and transforms data before it reaches the client, with a relational schema planned for user accounts and saved teams.
  • Exploring an LLM API to generate team recommendations, to learn how AI fits into a real application architecture.
  • React
  • TypeScript
  • Node.js

VisualOS

May – Jul 2026

The spark

I've always been a visual learner, and data structures only really clicked for me once I could picture them. I wanted to see the algorithms from my classes in motion, one step at a time. VisualOS became my way to learn by building: to animate each data structure I first had to understand it inside out, and the finished tool lets me explore new algorithms as I go.

An interactive visualizer that shows how algorithms change data structures, step by step.

  • Modular React and TypeScript component system that renders algorithm state changes in real time across multiple data structures.
  • Animated state transitions and responsive interactions built with React hooks, running smoothly on desktop and mobile.
  • Developed iteratively with Git branches and focused commits to keep a clean, reviewable history.

Three Card Poker Variation

May – Jun 2023

The spark

I built this in high school while learning Java, to show my computer science class how each core OOP concept could come together in a game everyone knows. Poker sounds simple on paper, but programming it is full of edge cases, like hands where the same cards could count as more than one ranking. Working through them taught me that the real challenge in programming isn't the obvious path, it's everything around it.

A Java card game with a complete gameplay loop, from betting to hand resolution.

  • Hand evaluation for all 10 poker rankings using an enum-based ranking system, checked in priority order so a straight flush is never misread as a straight or a flush.
  • Game logic, models and the Swing UI kept as independent components.
  • Java
  • Swing
  • OOP
